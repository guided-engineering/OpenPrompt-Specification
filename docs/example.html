An OPS example, end to end

One small change, followed from the request to the evidence. Everything on this page is read from examples/project/ when the site is built, and that example is executed by npm run example: the prompt and the worklog entries are validated and the prompt's checks are run again.

This is an illustrative example. It is not one of the measured study cases; those are on the results page.

1. The request

What a person wrote, in plain language:

Request

Slugs coming out of packages/slug look wrong in the article URLs. A title like a -- b turns into a------b, and -Hello! turns into -hello-.

Please make slugify produce clean slugs: one hyphen between words, and no hyphen at the start or the end. Two tests in packages/slug/test/slug.test.mjs already describe what I expect and currently fail.

Keep it small: do not add dependencies, do not change the function's name or signature, and do not touch the tests. Other packages in this repository are out of scope.

2. The OPS prompt

The same request as a task contract. It names the workspace, states an objective that can be checked, carries the constraints, orders the work, and lists the checks that decide completion. Nothing has been changed yet at this point; the person reads this and corrects it before any code is touched.

apiVersion: guided-engineering/v1
id: slug.clean-separators
version: 1
title: Make slugify collapse repeated separators and trim hyphens at the edges
agent: guided-engineer
workspace: ./packages/slug

objective: |
  `slugify` returns clean slugs: exactly one hyphen between words and no hyphen
  at the start or the end. `slugify('a  --  b')` returns `a-b` and
  `slugify('  -Hello!  ')` returns `hello`.

context: |
  `packages/slug` is a dependency-free ES module package tested with the Node.js
  built-in test runner. `src/slug.mjs` replaces every non-alphanumeric character
  with its own hyphen, so runs of separators survive as runs of hyphens and
  leading or trailing separators stay in the result. Two tests in
  `test/slug.test.mjs` describe the expected behavior and currently fail.
  The request comes from `request.md` at the repository root.

inputs:
  - src/slug.mjs
  - test/slug.test.mjs

dependencies:
  - Node.js 20 or newer is available as `node`

constraints:
  - Change only `src/slug.mjs`.
  - Do not edit, skip, or delete any test.
  - Do not add dependencies.
  - Keep the exported name `slugify` and its single-argument signature.
  - Leave every other package in the repository untouched.

requirements:
  - id: R1
    text: Runs of separator characters collapse into a single hyphen.
  - id: R2
    text: The result never starts or ends with a hyphen.
  - id: R3
    text: Existing behavior (lowercasing, diacritic stripping) is preserved.

steps:
  - id: reproduce
    title: Reproduce the failure
    requirements: [R1, R2]
    actions:
      - Run `node --test` in the workspace and record which tests fail and with which actual values.
      - Confirm the two failing tests are the separator-collapsing and edge-trimming tests; stop if anything else fails.

  - id: fix
    title: Correct the separator handling
    requirements: [R1, R2, R3]
    actions:
      - Read `src/slug.mjs` and identify the replacement that emits one hyphen per character.
      - Change the implementation so a run of non-alphanumeric characters becomes one hyphen and hyphens at either edge are removed.
      - Keep the normalization, diacritic stripping, and lowercasing steps as they are.

  - id: verify
    title: Verify the final bytes
    requirements: [R1, R2, R3]
    actions:
      - Run `node --test` in the workspace after the last edit and record the exit code and the pass and fail counts.
      - Confirm with `git status --short` that `src/slug.mjs` is the only modified file.

output:
  - file: src/slug.mjs
    rules:
      - Exports `slugify(input)` with the same signature.
      - Uses no dependencies.

verification:
  - id: unit-tests
    expect: All four tests in `test/slug.test.mjs` pass.
    run: node --test
    requirements: [R1, R2, R3]
  - id: scope
    expect: '`src/slug.mjs` is the only file changed inside or outside the workspace.'
    requirements: [R3]

stopConditions:
  - A test other than the two described ones fails before any change is made.
  - The fix cannot be made without editing a test or adding a dependency.

limits:
  repairAttempts: 2
  timeBudgetMinutes: 15

tags:
  - example
  - bugfix
createdBy: guided-engineering

Clean separators in slugify

The request was to execute the prompt slug.clean-separators, after the plan in 2026-11-13.slug-clean-separators-plan.md.

What was done

  • reproduce. node --test in packages/slug, before any edit, exited with code 1: two tests passed and two failed. The failing ones were the two the prompt describes. "collapses repeated separators into one hyphen" got a------b where a-b was expected, and "never starts or ends with a hyphen" got -hello- where hello was expected. Nothing else failed, so no stop condition applied.
  • fix. src/slug.mjs replaced every non-alphanumeric character with its own hyphen. The replacement now takes a whole run of such characters at once, and a second replacement removes a hyphen at the start and at the end. Two lines added, one removed. Normalization, diacritic stripping and lowercasing are untouched.
  • verify. node --test was run again after that edit, which was the last one.
