Where things live

RepositoryOwns
guided-engineering/OpenPrompt-SpecificationThe normative contract and the practice: schemas, validator, examples, conversion guide, study evidence, and this website.
guided-engineering/skillsThe ops-author and ops-execute Skills, their installation, their tests, and host integration notes.

The Skills carry the validator, which contains the schemas, and a copy of the contract text, so that they work in a project that has neither. That copy is synchronized by script and records the revision and hashes it came from. The contract is defined in one place only.

Schemas and validator

The schemas are served here at the addresses their $id names:

ArtifactSchema
OPS promptschemas/prompt.schema.json
Agent mapschemas/agents.schema.json
Worklog entryschemas/worklog.schema.json
Architecture Decision Recordschemas/adr.schema.json

The validator is one file with no dependencies. It needs Node.js 20 or newer.

curl -fsSLO https://guided-engineering.github.io/OpenPrompt-Specification/ops-validate.mjs
node ops-validate.mjs --help
node ops-validate.mjs .guides/prompts/prompt.my-task.yaml

Its third-party notices are in ops-validate.licenses.txt. A schema alone cannot check that an agent resolves, that a path stays inside its workspace or that a worklog entry claims no more than it shows; the validator does. A document is a valid OPS prompt when the validator accepts it.

Checking a change

git clone https://github.com/guided-engineering/OpenPrompt-Specification
cd OpenPrompt-Specification
npm ci
npm test              # contract tests: valid and invalid examples, CLI, bundle
npm run validate      # every active artifact of the repository
npm run check:refs    # links, schema references, retired vocabulary
npm run example       # the end-to-end example
npm run site          # regenerate this website into docs/

The rules of the repository are in AGENTS.md: the schemas are the single source of structure, the bundle and this site are generated, the invalid examples are invalid on purpose, and a failing check is reported with its output and never worked around.

Proposing a change

  1. Open an issue or a pull request against OpenPrompt-Specification for the contract, or against skills for a Skill.
  2. A change to the contract changes the schema first, then the validator, then the documents, and adds or adjusts an example that pins the behavior.
  3. A change to a Skill states which observed failure it addresses. The study protocol in .guides/testing/skills-study/ shows how a claim of improvement is tested.
