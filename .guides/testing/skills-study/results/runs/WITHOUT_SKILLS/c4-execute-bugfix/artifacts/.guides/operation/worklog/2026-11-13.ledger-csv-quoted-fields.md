# ledger.csv-quoted-fields: execute run

## Reproduce

`node --test` before any change: exit code 1, 7 tests, 4 pass, 3 fail. Exactly the
three quoted-field tests failed, so no stop condition applied. Actual values:

| Test | Input | Actual | Expected |
|---|---|---|---|
| keeps a comma inside a quoted field | `2026-01-05,"Rent, January",900.00` | `['2026-01-05', '"Rent', 'January"', '900.00']` | `['2026-01-05', 'Rent, January', '900.00']` |
| reads a doubled quote ... as one quote | `"say ""hi""",x` | `['"say ""hi"""', 'x']` | `['say "hi"', 'x']` |
| keeps whitespace inside a quoted field | `a," b ",c` | `['a', '" b "', 'c']` | `['a', ' b ', 'c']` |

The report test (`sums the amount column`) and the three plain-field tests passed.

## Fix

The code in `src/csv.mjs` no longer splits on every comma. `parseCsvLine(line)` now
scans the line one field at a time:

- If the first non-blank character of a field is `"`, the field is quoted. Its
  content is read up to the closing quote, `""` becomes `"`, and commas and
  whitespace inside the quotes are kept. Whitespace between the closing quote and
  the next comma is dropped. An unterminated quote runs to the end of the line.
- Otherwise the field runs to the next comma and is trimmed, as before.

The export name and single-argument signature are unchanged. No dependencies were
added, and no tests were changed.
